MiniMax speech reads the last assistant message after a successful live turn completes. A player row appears under each completed reply in the chat: play, pause, and drag the progress bar to seek. Configure credentials from the plugin's menu under Settings, Plugins, then Settings.

Requires Paseo 0.11.4 or newer. Desktop and web have seekable playback. Native iOS/Android playback is disabled because the public plugin audio API offers no seek control. Browser autoplay may require pressing Play.

The API key is sent to the daemon and stored in ~/.paseo-minimax-tts/settings.json (0600, directory 0700), never returned by a settings RPC. Model, voice, China/global region and the automatic speech mode are editable. Defaults are speech-2.8-hd, Chinese (Mandarin)_Warm_Girl, China, and automatic speech off. Selected reply text is sent to MiniMax and billed to your account.

Automatic speech has three modes. Off speaks only when you press Play. Synthesize makes the daemon generate speech for each new reply as soon as it completes, so Play is instant; it is billed even if you never play it. Play also plays the reply automatically while the Paseo app is open with the plugin loaded, queued in the order replies finish and played one after another, never initial history or a reconnect snapshot. A paused reply holds the queue until it finishes. Each connected client can play independently. The mode is a default for every chat, and a chat can override it from the Auto control in its player row; an override applies to replies that finish afterwards. Each player row shows whether its audio is not yet generated, being generated, ready to play instantly, or expired. The last 20 live replies are retained in daemon memory, not across restart. Generated audio is cached as MP3 files in ~/.paseo-minimax-tts/audio (private permissions, not encrypted), up to a size you set in Settings (512 MB by default) with the least recently used files removed first (a single recording larger than the limit is not cached), and you can see the usage and clear it there, so replaying a reply does not bill again, also after a plugin reload. A daemon restart clears the player rows, so older cached audio can no longer be reached from the chat and ages out of the cache. The cache key includes model and voice, so changing the voice generates new audio. There is no length limit: replies over 2000 characters are split at paragraph and sentence boundaries, synthesized part by part, and joined into one MP3, so cost grows with length. Each MiniMax request times out after 60 seconds, and synthesis can be canceled. Finished parts of a long reply are kept, so a retry after a failure only pays for the remaining parts.

SDK 0.11.4 has no final/channel marker on assistant messages. This plugin selects only the last assistant item after the latest user message on a completed lifecycle event; it never joins earlier assistant updates, reasoning, or tools. Providers that split a final response across messages yield only the last part. A provider that ends successfully with commentary indistinguishable from a final message cannot be classified perfectly by this SDK.
